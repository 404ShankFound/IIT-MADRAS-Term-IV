WHAT TO CHANGE IN EASY_EXAM_TEMPLATE.PY FOR EVERY PREDICTED QUESTION
===================================================================

BASE TEMPLATE RIGHT NOW
-----------------------
Use the same standard names in every final exam answer:

encrypt_data(data, key, algorithm, **options)
decrypt_data(encrypted_data, key, algorithm, **options)
generate_keys(algorithm, **options)
hash_data(data, algorithm)
sign_data(data, private_key, algorithm, **options)
verify_signature(data, signature, public_key, algorithm, **options)

Algorithm-specific names mentioned later in this guide are the small helper
implementations inside each lab file. Call them from the standard functions;
do not rename the standard functions used by menus.

The current EASY_EXAM_TEMPLATE.py contains:

- USERS: student1, student2, faculty1 and hod1
- ROLE_PERMISSIONS: student, faculty and hod permissions
- DES-CBC: encrypt_data(), decrypt_data(), des_encrypt(), des_decrypt()
- SHA-256: hash_data()
- RSA signatures: sign_data(), verify_signature()
- JSON storage: load_records(), save_records()
- Keyboard/file input: get_record_from_user()
- Student actions: student_upload(), student_view(), student_menu()
- Faculty actions: faculty_verify_record(), faculty_menu()
- HoD actions: hod_menu()
- Authentication: login(), main()

In most role-based questions, keep login(), load_records(), save_records(),
choose_record() and the overall while-loop structure. Change only the settings,
crypto functions, record dictionary fields and role-menu actions.


QUESTION 1 - SECURE HOSPITAL RECORD SYSTEM
==========================================
Best starting file: EASY_EXAM_TEMPLATE.py
Amount of change: SMALL

1. Change USERS:
   student1 -> patient1, faculty1 -> doctor1, hod1 -> admin1.
   Change role strings to patient, doctor and hospital_admin.

2. Change ROLE_PERMISSIONS:
   patient: upload, view_own
   doctor: decrypt, verify, view_assigned
   hospital_admin: view_hash, verify

3. Replace DES with AES-128:
   - Import AES instead of DES.
   - Change DES_KEY to a 16-byte AES_KEY.
   - In encrypt_data(), use AES.new(AES_KEY, AES.MODE_CBC).
   - Use AES.block_size in pad().
   - In decrypt_data(), split the first 16 bytes as IV and use AES.block_size.
   The present Base64 IV+ciphertext storage design can remain unchanged.

4. Rename record fields for readability:
   student -> patient
   encrypted_record -> encrypted_report
   uploaded_at -> report_uploaded_at

5. Rename the role functions:
   student_upload/view/menu -> patient_upload/view/menu
   faculty_verify_record/menu -> doctor_verify_report/menu
   hod_menu -> hospital_admin_menu

6. Add assigned_doctor to every record. In choose_record(), a Doctor must see
   only reports where record["assigned_doctor"] equals the logged-in username.

7. Keep unchanged:
   hash_data(), RSA key generation, sign_data(), verify_signature(), JSON
   storage, timestamps, keyboard/file input and verification history.

FAST DECISION RULE DURING THE EXAM
==================================

If the question has 3 roles + encryption + signature + hashing:
    Start with EASY_EXAM_TEMPLATE.py.

If it mainly asks DES/AES/3DES or modes/timing:
    Start with LAB_2_ADVANCED_SYMMETRIC.py.

If it asks RSA/ECC/ElGamal/DH encryption or file transfer:
    Start with LAB_3_ASYMMETRIC.py.

If it asks key generation/distribution/revocation/Rabin/DRM:
    Start with LAB_4_KEY_MANAGEMENT_ACCESS_CONTROL.py.

If it asks socket hashing or collision comparison:
    Start with LAB_5_HASHING.py.

If it asks ElGamal/Schnorr/RSA signatures or CIA triad:
    Start with LAB_6_DIGITAL_SIGNATURE.py.

If it asks classical ciphers:
    Start with LAB_1_BASIC_SYMMETRIC.py.
